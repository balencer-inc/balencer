# client-deck — 議事録を、出せる資料に仕上げる工程

クライアントに出す資料（戦略書・提案書・報告書）を **HTML で組んで A4横PDF で納品する** ための固定手順。
2026-08-26、加藤梨紗さんが Miracle nurse 様向けマーケティング戦略書（10ページ）を作った流れを型にした。中身の質より先に **順番** が効く。

**中身は誰が書くか**: 提案・戦略の中身は `consulting`、コピー・企画は `creative` の担当。このスキルは **仕上げの工程** を受け持つ。中身と工程は分けて考える。

---

## 大原則 — いきなりHTMLを書かない

失敗パターンは決まっている。**材料が散らばったままチャットで資料を作り始める**こと。
順番はこう固定する。

```
材料を1箱に集める → プロット（文書）を確定 → 見た目を1枚選ぶ → HTML化 → グリッド整列 → 検品
```

見た目に手を入れるのは **プロットが確定してから**。逆にすると、文章を直すたびにレイアウトが崩れて何往復もする。

---

## STEP 0 — 材料を1箱に集める（ここを飛ばさない）

資料の話が出たら、**まず箱を作って材料を全部そこに入れる**。チャットに貼るだけで済ませない。

```bash
mkdir -p docs/clients/<顧客スラッグ>/00_材料
```

- 入れるもの: 議事録・ヒアリングメモ・先方から受け取った資料・数字（契約金額・実績・KPI）・既存LPやサイトのURLメモ・写真素材
- 顧客スラッグの正は `docs/clients/README.md` の対応表。新規なら先に1行足す
- 箱の切り方は CLAUDE.md §3（`01_提案/` `02_契約・見積/` などの既定構成）に従う
- **材料が足りない状態で書き始めない**。足りないものがあれば、この時点で阿部さんに聞く（数字・固有名詞・先方の言い回し）

> 阿部さんが飛ばしがちなのがこの STEP 0。秘書は資料の依頼を受けたら、書き始める前に必ず箱の場所を確認して報告する。

---

## STEP 1 — プロット（文書）を作る

HTMLの前に、**md で構成を書き切る**。1ページ＝1メッセージで、ページ順に並べる。

- 保存先: `docs/clients/<顧客>/01_提案/<案件>-plot.md`
- 各ページに **「英語ラベル」「日本語見出し」「そのページで言い切る1文」** を必ず書く
- 数字は根拠まで書く（「月66万円」だけでなく「うち広告費3万円」まで）
- 写真が要る箇所は `[写真: 〜]` と書いて空けておく（素材は後で用意。画像生成で埋める場合もこの段で決める）

**効いていたページ構成**（戦略書10ページの実例。案件に合わせて増減する）

| # | ページ | 役割 |
|---|---|---|
| 01 | 表紙 | 提案の骨子を表紙の右側に置き、**1枚目で結論が見える**ようにする |
| 02 | エグゼクティブサマリー | 現状→結果→課題→提案の4カード。結論を先に |
| 03 | 事業構造・収益モデル | 共通認識の整理。相手の事業を相手より整理して見せる |
| 04 | 現状課題 | 投資と成果のギャップを数字で可視化 |
| 05 | 市場・競合 | ポジショニングマップ。なぜ差別化が必須か |
| 06 | ターゲット／ペルソナ | 誰に届けるかを確定。回収シミュレーション表 |
| 07 | 差別化ポジショニング | 何を訴求するか |
| 08 | 戦略・ファネル | どう届けるか（認知→興味→検討→行動→継続） |
| 09 | 体制と予算配分 | 座組図＋ビフォーアフターの予算バー |
| 10 | KPI・ロードマップ・ネクストアクション | 貴社／弊社のアクションを分けて書く。契約条件を添える |

**この構成が効く理由**: 相手の事業構造を整理して見せる（03）→ 事実で課題を突く（04）→ 打ち手（07-08）→ 誰が何をやるか（09-10）。**提案が「意見」でなく「診断」になる**。提案・打合せ資料のトーン指針（挨拶不要／要件整理が主役／診断型）と一致する。

---

## STEP 2 — プロットを阿部さんに見せて微修正

**ここで必ず一度止める。** 数字・固有名詞・言い切りの強さは、確定してから見た目に進む。
プロットが直った状態で STEP 3 へ。

---

## STEP 3 — 見た目を1枚選ぶ（design-md）

`design-md` スキルを使い、ギャラリー472ブランドから1枚選んでルールを取り込む。

```bash
open "https://kzhrknt.github.io/awesome-design-md-jp/gallery.html"
curl -s "https://raw.githubusercontent.com/kzhrknt/awesome-design-md-jp/main/design-md/<slug>/DESIGN.md"
```

- **毎回ちゃんと選ぶ**。「今回は適当でいいか」で飛ばすと、資料の見た目が毎回ブレる
- 選び方の目安: クライアントの業種・トーンに寄せる／赤系アクセントで数字を立てたいなら `meiji`（実例で使用）／和・老舗なら `toraya` `nakagawa`、BtoB SaaS なら `smarthr` `loglass`、公的・堅い相手なら `dads` スキル
- **バレンサー名義の対外物は自社CI（v3「墨」）が優先**。デザインmdは参考の一枚であって上書きしない
- 適用したブランド名を、HTMLの冒頭コメントと報告に残す（後で再現・差し替えできるように）

---

## STEP 4 — HTML化（A4横・PDF出力前提）

プロンプトの型:

> このプロットを、`<ブランド>` の DESIGN.md を参照して HTML で資料に仕上げて。A4横で、PDFでDLできるようにして。

**技術要件（毎回これを満たす）**

```css
@page { size: A4 landscape; margin: 0; }
```

- 1ページ ＝ 固定サイズの `.page` ブロック。`page-break-after: always` で切る
- 画面表示でもPDFでも同じ見た目になるよう、`width` はmmまたは固定pxで決め打つ
- Webフォントは Google Fonts（Noto Sans JP）を `<link>` で読み込む。日本語の line-height 1.7〜2.0、letter-spacing 0.04〜0.1em は DESIGN.md 側の指定に従う
- 図（ポジショニングマップ・座組図・予算バー）は **画像にせず HTML/CSS で組む**。後から数字を直せる

**PDF書き出し**（estimate スキルと同じレシピ）

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --print-to-pdf="<出力パス>.pdf" --no-pdf-header-footer "<HTMLパス>"
```

## STEP 5 — グリッド整列（ここで見た目が一段上がる）

初回のHTMLは、たいてい要素の大きさがバラバラになる。**必ずこの指示を一度入れる**。

> グリッドデザインにして、見た目の美しさと整然としたレイアウトに修正して。同じ役割の要素は同じ大きさの枠に揃えて。

**揃えるべき具体**

- 横並びカードは **等幅・等高**。中身の文字数が違っても枠は揃える（`display: grid` ＋ `grid-template-columns: repeat(4, 1fr)`）
- カード内の構造を固定する: **番号ラベル → 見出し → 箇条書き → 下端にメトリクスのチップ**。チップを `margin-top: auto` で下端に寄せると高さが揃って見える
- ページ上部の型を全ページ共通にする: **小さい英語ラベル → 大きい日本語見出し → 右上に一言タグ**（「結論を先に」「共通認識の整理」「なぜ差別化が必須か」）
- フッターも全ページ共通: **左に「CLIENT × 自社」／右にページ番号**
- 結論は **色帯（淡い生成りの帯）に載せて最上部**に置く
- 数字は特大＋単位を小さく（`3万円` の「万円」だけ小さく）。**悪い数字はアクセント色、良い数字は黒**でコントラストを作る
- 表は3〜4行に絞る。長い表はカードに分解する

**やらないこと**: 蛍光イエローのマーカー風下線／全角ダブルクォート（`“”`）／アクセント色を2色以上使う／情報量で埋める（文章過多は「デザインは綺麗だが刺さらない」の原因そのもの）

---

## STEP 6 — 内容微修正 → 検品 → 納品

1. 内容を最終調整（数字・敬称・社名の表記ゆれ）
2. **`ai-judges`** で叩く（対外文書。4人の審査員で弱いところを潰す）
3. **`python3 scripts/brand_lint.py <ファイル>`** で検品（対外成果物は必須）
4. PDF書き出し → `open` でブラウザに出して阿部さんに見せる（mdのまま報告しない）
5. 成果物を `docs/clients/<顧客>/01_提案/` に保存 → コミット＆プッシュ → main へマージ

## メモ

- 資料そのものが再利用資産になる。**3回以上同じ構成で作ったら、そのHTMLをテンプレート化**して固定する（繰り返し作業の昇格ルール）
- 参考の実例: 加藤梨紗さん作「株式会社Miracle nurse 御中 マーケティング戦略書」（2026-08-25／10ページ／design-md `meiji`）。**他社の契約金額・交渉状況を含むため社外に出さない**
- この工程の記録は `docs/_knowledge/creative.md`（2026-08-26 のエントリ）
