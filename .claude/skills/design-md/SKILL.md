# デザインmd — ギャラリーから選んで着手する

資料・LP・スライドを作る時、いきなり作り始めず **「どのデザインで作るか」をギャラリーから1枚選んでから着手する** ためのスキル。
選択肢は [awesome-design-md-jp](https://github.com/kzhrknt/awesome-design-md-jp)（@kzhrknt）の **472ブランド**。各ブランドのサイトを実測（Puppeteer computed style）した DESIGN.md が、フォント・カラー・余白・角丸まで具体値で入っている。これをそのままAIの作図ルールに使う。

正本メモ: [reference_design_md.md]（memory）。slug索引はこのフォルダの `slugs.txt`。

## いつ使うか
- 「デザインmd」「ギャラリーから選んで」「○○風で作って」「デザインテーマ決めたい」と言われた時
- 資料・LP・スライド・提案デッキ・社内報などの **見た目を決める段**（着手直前）
- クライアントの「××みたいな雰囲気で」を具体化したい時（例: 「無印みたいに」→ muji のDESIGN.md）

## 3ステップ（これを固定運用にする）

### STEP 1 — 選ぶ（ギャラリーをブラウザで開く）
阿部さんがブランドをまだ決めていない時は、**公式ギャラリーを開いて視覚で選んでもらう**。
```bash
open "https://kzhrknt.github.io/awesome-design-md-jp/gallery.html"
```
- ギャラリーはスクショ付き一覧。上流が更新され続けるので常に最新。
- 「これがいい」と言われたらブランド名を受け取る。**すでに「○○風で」と名前が出ている時はSTEP 1を飛ばして STEP 2 へ。**

### STEP 2 — 取り込む（slug変換 → raw取得）
1. ブランド名を `slugs.txt` で slug に変換（「ユニクロ」→ `uniqlo`）。和名は索引冒頭の対応表を参照。曖昧なら候補を2〜3個提示して確認。
2. raw で DESIGN.md を取得して読む:
   ```bash
   curl -s "https://raw.githubusercontent.com/kzhrknt/awesome-design-md-jp/main/design-md/<slug>/DESIGN.md"
   ```
3. プレビューを見せたい時（任意）: `open "https://kzhrknt.github.io/awesome-design-md-jp/design-md/<slug>/preview.html"`
4. 索引にない/新しく増えていそうな時は API で最新一覧を取り直す（`slugs.txt` 冒頭にコマンドあり）。

### STEP 3 — 着手（ルールを適用して作る）
取得したDESIGN.mdを **その資料の作図基準** として使う。
- カラー・フォント・line-height・余白・角丸・CTAの形（pill等）を、DESIGN.md の実測値どおりに反映する。
- 日本語調整はDESIGN.md側に既に入っている（和文フォント優先指定・line-height 1.7〜2.0・letter-spacing 0.04〜0.1em）。追加で崩さない。
- 作った資料の冒頭コメント or 報告に「デザインmd: <ブランド名>（awesome-design-md-jp）を適用」と一言残す（後で再現・差し替えできるように）。

## ブランド規律（重要なガードレール）
- **バレンサー自社の対外物** は CIの正本が最優先。デザインmdは "参考の一枚" であって、自社CIを上書きしない。
  - 自社CI正本: v3「墨」／v2ローズゴールド（[project_balencer_site_rebuild_2026]・[project_balencer_design_system]）。迷ったら自社CIを優先し、デザインmdは補助的に混ぜる。
  - `brand-lint`（対外検品）の規律も従来どおり通す。
- デザインmdが主役になるのは主に **クライアント案件・探索・「○○風」の再現**。他社ブランドの丸写しをバレンサー名義の対外物に使わない。
- 既存の禁止事項は維持: 蛍光イエローのマーカー風下線を使わない／全角ダブルクォート禁止／AIっぽい読点コピー禁止。デザインmdを当てても、これらの規律が勝つ。
- これらは各企業の公式デザイン仕様書ではなく公開CSSからの実測値（ライセンス・商標に配慮。あくまで社内制作の下敷き）。

## メモ
- 保存先・作り方の箱はCLAUDE.md §3のとおり（顧客案件なら `docs/clients/<顧客>/`、自社なら該当フォルダ）。デザインmd適用は "作り方" の一部で、成果物の置き場は変わらない。
- 3回以上同じブランドで作るようになったら、そのDESIGN.mdをリポジトリにキャッシュ保存して固定テーマ化することを提案（繰り返し作業の昇格ルール）。
