# 月次レポート — 議事録から専務向け1枚を作る

顧客の**上位意思決定者（専務・社長）へ毎月出す報告レポート**を、Notion議事録DBから組む型。
定例に出ていない役員が「今月どんな会議で何を話したか」を1枚で把握できる状態を作ることが目的。

対外成果物なので `brand-lint` を必ず通す。デザインは `design-md` から選んだテーマを適用する。

---

## 0. 対象顧客の設定表

新しい顧客を追加する時はこの表に1行足す。

| 顧客 | スラッグ | 議事録の絞り込み | 除外する会議 | デザインmd | 出力先 |
|---|---|---|---|---|---|
| 睦備建設株式会社 | `mutsubi` | `顧客='睦備'` または `関連顧客` に `25e53269fc5e80d8809cde70fe7cb748` | **gini定例（ベンダー間会議）は材料から除外** | `meiji`（明治） | `docs/clients/mutsubi/月次レポート/<YYYY-MM>/` |

共通の定数:
- 議事録DB data source: `collection://21753269-fc5e-80ee-b22a-000bacba9a0b`
- 顧客管理DB data source: `collection://2ef07b20-436f-435d-a869-bc57eeb7c57c`
- Notion は **claude.ai の Notion コネクタ**（`mcp__claude_ai_Notion__*`）を使う。`notion-mcp`（APIトークン方式）は401で使えない

## 0. 先にタグの抜けを埋める（`notion-tag-fill`）

議事録の顧客タグが空だとレポートから漏れる。**材料抽出の前に `notion-tag-fill` スキルで空タグを埋める**。
毎月やる必要はない。下のカウントで空が溜まっていたら実行する。

```sql
SELECT SUM(CASE WHEN "顧客" IS NULL AND "関連顧客" IS NULL THEN 1 ELSE 0 END) AS 両方空
FROM "collection://21753269-fc5e-80ee-b22a-000bacba9a0b"
```
> 2026-08-27 時点で 50件（推定できない人名のみ・タイトル空・select未登録の会社）。ここは埋まらない前提。

## 1. 材料を抽出する（SQL 1発）

```
mcp__claude_ai_Notion__notion-query-data-sources
  data_source_urls: ["collection://21753269-fc5e-80ee-b22a-000bacba9a0b"]
  query: SELECT "date:日付:start" AS d, "タイトル", "顧客", "会議タイプ", url
         FROM "collection://21753269-fc5e-80ee-b22a-000bacba9a0b"
         WHERE ("顧客" = '睦備' OR "関連顧客" LIKE '%25e53269fc5e80d8809cde70fe7cb748%')
           AND date("date:日付:start") >= date('<月初>')
           AND date("date:日付:start") <= date('<月末>')
         ORDER BY d ASC
```

**重要な前提（実測で確認済み・2026-08）**
- DBプロパティの `内容`・`次のアクション`・`重要度` は**ほぼ全件空**。中身は**ページ本文のAI議事録（`<meeting-notes><summary>`）にある**
- したがって一覧を取ったあと、対象ページを1件ずつ `mcp__claude_ai_Notion__notion-fetch` で開いて本文を読む。1ページに `<meeting-notes>` が複数入っていることがある（例: freee会計8/27はデモ回と方針回の2本）
- **顧客タグが空の議事録は拾えない**（DB全体で約2割がnull。「AI会議」等が該当）。取りこぼしの可能性を必ず阿部さんに報告する
- `<transcript>` は読まない（トークンの無駄。`summary` で足りる）

---

## 2. 機微の線引き（最重要・事故ポイント）

**ベンダー間会議（睦備ならgini定例）には、そのまま出せない情報が入っている。**
実例: 見積の内訳交渉（248万→200万に圧縮したい）、バッファーの圧縮方針、バレンサー側の工数管理。

- 睦備の現在の設定は「**gini定例は材料から除外**」（2026-08 阿部さん判断）
- ただし「開発ベンダーとの実務定例を週次で実施（日付のみ）」の一行注記は入れる。稼働している事実は伝え、中身は出さない
- クライアント同席の会議で出た金額（例: freeeからの見積感覚値）は、**確定額ではない旨を明示して**載せる。数字を先に固定しない
- 承認済みの事実は書いてよい（例: 開発費は専務へご報告のうえ進行が決定）が、**金額そのものはベンダー会議由来なら書かない**

## 3. プロット（4ブロック固定）

| ブロック | 中身 | 分量の目安 |
|---|---|---|
| ① 今月の会議 | 日付・会議名・主なテーマの表。＋ベンダー定例の注記 | 3〜6行 |
| ② 今月のポイント | 役員が知るべき変化を3つ。番号付き | 3項目×2行 |
| ③ テーマ別の進捗 | 領域ごとにカード。**6枚まで**（5領域＋お客様の声） | 各3〜4項目 |
| ④ 来月の重点 ／ ご判断をお願いしたいこと | 左右2カラム。期日つき／判断待ちを明示 | 各4件 |

- 「お客様の声」カードは効く。入居者・顧客からの意見が議事録にあれば必ず1枚立てる
- ③は**進捗と決定**を書く。会議での発言の再現ではない
- ④の「ご判断」は**専務が決めないと止まるもの**だけ。作業依頼を混ぜない

## 4. HTML化 → PDF

前月のHTMLを**テンプレとしてコピーして中身を差し替える**のが最短。
テンプレ原型: `docs/clients/mutsubi/月次レポート/2026-08/月次報告_睦備建設_2026-08.html`

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --print-to-pdf="<出力>.pdf" --no-pdf-header-footer "<HTML>"
```

**A4横1枚に収める検証は必ずやる**（`.page` は `height:210mm; overflow:hidden` なので、**はみ出しても1ページのPDFができてしまい気づけない**）。

```bash
python3 scripts/report_fit_check.py "<HTML>"
```
`.page` の高さ制約を一時的に外したコピーをPDF化し、2ページ以上になったら「はみ出し」と判定する。`[OK] 1枚に収まっています` が出るまで詰める。

目視でも見たい時（レイアウトの当たりを確認する用）:
```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless \
  --screenshot="/tmp/check.png" --window-size=1123,794 \
  --force-device-scale-factor=2.2 --hide-scrollbars "<HTML>"
```

詰める順番:
1. テーマカードの文量（`.sub` を1〜2行に）— 効果が最も大きい
2. カードの項目数（4→3に統合）
3. `.theme li` の font-size / line-height
4. ヘッダーの `.title` と `.rule`

## 5. 検品

```bash
python3 scripts/brand_lint.py "<HTML>"
```
- ERROR 0件が条件
- **「さん」のWARNは顧客ご自身の社員名なら却下**（先方の社員を「様」と書くと不自然）。ベンダー・第三者名なら直す
- 全角ダブルクォート禁止／黄色マーカー風下線禁止／AIっぽい読点コピー禁止は従来どおり

## 6. 保存と連絡

**月ごとに貯める。過去月は絶対に消さない・上書きしない。**

- 置き場: `docs/clients/<スラッグ>/月次レポート/<YYYY-MM>/`
  - 必ず**その月の新しいフォルダを作る**。前月フォルダの中身を書き換えるのは同月内の差し替えのみ
  - ファイル名: `月次報告_<顧客名>_<YYYY-MM>.html` と `.pdf`（HTMLとPDFの両方を残す。HTMLがないと翌月のテンプレにできない）
- **`月次レポート/README.md` の「各月」テーブルに1行追記する**（会議数・除外した会議・HTML/PDFへのリンク）。ここが月次の索引なので、追記を忘れると貯めた意味が薄れる
- **PDFの複製をデスクトップにも置く**（メール添付・ファイル選択ダイアログ用）。gitが正本、デスクトップは受け渡し用の複製
  ```bash
  D="$HOME/Desktop/<顧客略称> 月次レポート" && mkdir -p "$D"
  cp "docs/clients/<スラッグ>/月次レポート/<YYYY-MM>/月次報告_*.pdf" "$D/"
  ```
  睦備は `~/Desktop/睦備 月次レポート/`。PDFのみをフラットに貯める（HTMLは置かない）
- PDFを `open` で開いて阿部さんに見せる
- 取りこぼし（タグ空の議事録・未開催の会議）と、機微で落とした項目を必ず報告する
- `docs/_knowledge/` に判断の変更があれば追記し、main へマージする

## 運用（自動化の現状・2026-08）

**カレンダー予定 → 一言で起動**が現状の運用。無人での完全自動生成はできない。

- Googleカレンダー: **毎月最終平日 16:00**に「睦備建設様 月次レポート作成」の繰り返し予定（30分前に通知）
- 通知が来たら balencer リポジトリで「睦備の月次レポート作って」と言う。このスキルが1〜6を実行する

### なぜ無人にできないか（試して分かったこと）
1. **PDF化にローカルのChromeが必要**。クラウドの定期実行（`schedule` スキルのルーティン）にはChromeがなく、PDFまで作れない
2. **Notionはclaude.aiコネクタ経由**でしか読めない（`notion-mcp` のAPIトークンは401）。ヘッドレス/cron実行ではコネクタが外れることがある
3. `CronCreate` はセッション限定で7日で失効するため、月次サイクルには使えない

→ 将来無人化するなら、Notion Integration Token を発行して `notion-mcp` を復活させ、ローカルの launchd で回す構成になる。現状はカレンダー起動で十分速い（3分程度）。
