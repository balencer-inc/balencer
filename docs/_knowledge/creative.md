## 2026-08-26 議事録 → クライアント提出資料の作り方を型にした（client-deck スキル新設）

加藤梨紗さんが Miracle nurse 様向けマーケティング戦略書（10ページ・A4横PDF）を作った流れを、阿部さんの指示で社内の標準フローに昇格させた。`.claude/skills/client-deck/` が正本。

### なぜ型にしたか
出来上がりの質が高かった理由は、センスではなく**順番**だった。阿部さんの自己申告で「プロジェクト（箱）を作って材料を全部入れてから始める、をやっていない」という抜けが特定できたので、そこを STEP 0 として明示的に固定した。

### 固定した6手順
材料を1箱に集める → プロット（md）を確定 → design-md で見た目を1枚選ぶ → HTML化（A4横） → グリッド整列 → 検品（ai-judges → brand-lint）→ PDF。

- **見た目に手を入れるのはプロット確定後**。逆にすると文章を直すたびにレイアウトが崩れて往復が増える
- **プロット段階で一度必ず止めて阿部さんに見せる**。数字・固有名詞・言い切りの強さはここで確定させる
- **「グリッドデザインにして、同じ役割の要素は同じ大きさの枠に揃えて」の一言を必ず入れる**。初回HTMLは要素の大きさがバラつくのが常で、この指示だけで見た目が一段上がる

### 効いていたページ構成（診断型の順番）
表紙（骨子を表紙に載せて1枚目で結論を見せる）→ エグゼクティブサマリー → **相手の事業構造の整理** → 現状課題を数字で可視化 → 市場・競合（ポジショニングマップ）→ ターゲット／ペルソナ → 差別化 → ファネル → 体制と予算配分 → KPI・ロードマップ。

相手の事業を相手より整理して見せてから課題を突くので、**提案が「意見」ではなく「診断」になる**。提案・打合せ資料のトーン指針（挨拶不要・要件整理が主役・診断型）とそのまま一致していた。

### レイアウトの具体（実測して抽出）
- 横並びカードは等幅・等高。カード内は「番号ラベル→見出し→箇条書き→下端にメトリクスのチップ」で構造を固定し、チップを `margin-top:auto` で下端に寄せると高さが揃う
- 全ページ共通の頭: 小さい英語ラベル → 大きい日本語見出し → 右上に一言タグ（「結論を先に」「共通認識の整理」）
- 全ページ共通のフッター: 左「CLIENT × 自社」／右ページ番号
- 数字は特大＋単位だけ小さく。**悪い数字はアクセント色・良い数字は黒**でコントラストを作る（広告費3万円／成約0件 が刺さっていた）
- 図（ポジショニングマップ・座組図・予算ビフォーアフター）は画像にせず HTML/CSS で組む。後から数字を直せる
- アクセント色は1色だけ。文章過多にしない（「デザインは綺麗だが刺さらない」の原因そのもの）

### design-md の使用が定着していなかった件
阿部さんから「毎回デザインmdにいいのがあるのに、ちゃんと使えていなかった」との反省。**STEP 3 として工程に埋め込む**ことで、選ぶのを飛ばせない形にした。今回は `meiji`（明治レッド #d90000・line-height 1.8・letter-spacing 0.06em）を適用。
