## 2026-08-17 外注仕入れに利益を乗せる見積（H2O・小口スポット）

**案件**: 株式会社エイチ・ツー・オー 福岡新店舗の会員登録タグ付与URL発行。仕入 8,000円（Bonobo 廣田真美さん）→ 客先 30,000円（税抜）／33,000円（税込）。

- **決定した値付け**: URL発行 20,000円＋ディレクション費 10,000円の2行立て。粗利22,000円・粗利率73.3%
- **却下した案とその理由**: 機械的な「仕入×1.3＝10,400円」「粗利率30%＝11,430円」はいずれも阿部さんが不採用。**小口スポットでは仕入率ベースの積み上げは使わない**。仕入が数千円でも、要件整理・外注手配・検証・報告というディレクションの手間は案件規模に比例しないため、仕入の倍率ではなく「この作業に払ってもらう妥当額」で置く
- **型として残す**: 外注仕入れに乗せる見積は「①仕入を含む成果物の値（丸めた額）＋②ディレクション費（別行）」の2行構成。ディレクションを別行にすると、次回以降の同種依頼で成果物の値だけを反復でき、値付けの説明もしやすい
- **原価の扱い**: 仕入・粗利は git 側の社内メモにのみ記載し、客先へ出す Notion ページには一切載せない（PDF化してそのまま送付するため混入が事故になる）
- **小口の相場観**: 仕入8,000円クラスの追加設定でも税込33,000円。反復発生する顧客なので、都度見積の手間自体が次の自動化候補



## 2026-09-03 invoice スキルを作った（請求書の発行を型化）

`.claude/skills/invoice` を新設。`estimate` の構成（HTML＋PDF＋検算）を踏襲しつつ、請求書固有の3点を内蔵した。

- **定数は探さない** — 登録番号・住所・振込先・採番・書式・社印の在り処は `docs/company/invoice-constants.md` が正本。スキルは冒頭でここを読む。起票時の学びは「毎回詰まるのは書式ではなく定数の不在」だった
- **検算スクリプト** `scripts/invoice_calc.py` — 明細JSONを渡すと税抜換算・税率別集計・契約税込総額との突合を出す。**突合がOKになるまでHTMLを作らない**運用にした
  - 税込契約の換算は行ごと `round(税込 ÷ 1.1)`、消費税は税率ごとの小計に `floor` を1回。ファイアープレイス様の実績（374,200円）で完全一致を確認
  - 端数処理を明細ごとにやるのはインボイス制度で不可。スクリプト側で構造的に防いでいる
- **雛形** `assets/invoice-template.html` — 実戦投入した請求書（社印の `mix-blend-mode:multiply`・別紙内訳ページ・8%対象行）をそのままプレースホルダ化したもの。別紙が不要なら2枚目の `.page` ごと削除する

判断として内蔵したもの: 固定報酬か実績精算かの読み分け／法人への源泉徴収は原則不要／宛名は契約書本文の表記が正。

**残**: SKILL.md §6「作成から送付までの流れ」は暫定。阿部さんの実運用（誰に・どの経路で送り、控えをどこに残すか）をヒアリングして上書きする。

## 2026-09-03 請求の全工程を実地確認し、月次バッチ化した

阿部さんの実運用（①売掛金一覧 → ②Drive月次PDF → ③売掛金管理表 → ④営業管理数字マスター → ⑤メール/LINE/billone）を Drive の実ファイルで確認し、①〜④の列構成まで [invoice-constants.md](../company/invoice-constants.md) に記録した。

- **①は「予定表かつ入力の正本」**。顧客別タブで未来月の行が先に入っており、**請求書NOが空の行＝未発行**。ここが月次バッチの対象になる
- **①はこのままでよい**と判断した。揺らぎの原因は表の形ではなく2点だけ ── (a)案件名が複数明細を1セルに詰めたフリーテキスト、(b)備考に自分用メモと請求書掲載文が混在。この2点はgit側の請求先マスタと `remarks` で吸収できるので、阿部さんの入力習慣を変える必要はない
- **入金予定日は①が唯一の正**。契約条件から推定すると外れる（北麓様は「末締め翌末」ではなく請求日+60日。07-078の実績で確認）
- **③は和暦・税込、④は西暦・税抜**。同じ請求を2つの単位で書くので、バッチが両方のTSVを吐く形にした
- ③④への書き込みはスプレッドシートAPIが無いため貼り付け行の生成まで。手作業は月1回×2回の貼り付けに縮まる

**採番事故**: 07-079 は 2026/8/17 にトライ・ワークス様へ発行済みだったが、リポジトリ側の採番表が7月末で止まっていたためファイアープレイス様に同番号を振っていた。→ 07-085 に振り直し。**採番表はスプレッドシート①が正、gitの表は写し**という関係を明記した。

`invoice_build.py` は生成額を①の「本体税込」と全件突合し、1円でも違えばNGで止まる。ファイアープレイス様の手作りHTMLとバイト単位で一致することを回帰テストとして確認済み。
