③ WordPress のバージョンアップとセキュリティ

結論（3行）

  1. 乗っ取り対策としては、コアのバージョンは3番目の論点。ログインまわりとプラグインを固めれば、リスクの大半は今週落ちます。150〜200万を今すぐ払わずに守れます。
  2. ただし更新しなくていい、ではありません。更新の本当の動機は「安全になるから」ではなく、速度と、直せる状態を保つためです（理由は後述）。
  3. 「重い」は攻撃対策とは別問題ですが、根本原因の第一候補がPHP 7.4なので、速度の話としては更新と同じ話になります。無料でできる切り分けとDB掃除が先です。

「更新しなくてもいい」ではない理由

コアのバージョン差が危険度3番目、というのは「上げなくていい」という意味ではありません。放置すると次の2つが効いてきます。

  1. プラグインが「直せない状態」に固まる。古いコアに合わせて古い版のプラグインで止まるため、そのプラグインに脆弱性が見つかっても上げられません。半年〜1年で効いてくるリスクです。
  2. 5.8/5.9系へのセキュリティ修正が、いつまで続くかは誰も約束していない。今は当たっていますが、期限の保証はありません。

つまり 短期＝守りで止血、中期＝更新は必要、という二段構えです。更新の説明を「危険だから」ではなく「速くなる／直せる状態を保つ」に置き替えたほうが、実態にも合っています。

現状の危険度をどう見るか

いただいたバージョン一覧を見ると、10サイトすべてが 5.8系・5.9系です。数字だけ見ると「4世代前で放置」に見えますが、枝番に注目してください。5.8.15 / 5.9.16 という枝番は、そのブランチに出続けているセキュリティ修正が当たっている状態を示しています（WordPressは旧ブランチにも重要な修正を戻す運用）。つまりコア本体が穴だらけで放置、という状態とは少し違います。

3つの方向性

A案｜守りを先に固める（今週〜2週間・低コスト）

崩れるリスクゼロで今すぐできることが、実はかなり残っています。

  • 管理画面へのアクセス制限（IP制限・国外アクセス遮断・ログイン試行回数制限）。エックスサーバーの標準機能で設定可能
  • 二要素認証の導入
  • 管理者アカウントの棚卸し（退任者・外注先のアカウントが残っていないか）
  • 自動バックアップの動作確認と、実際に戻せるかのテスト
  • 使っていないプラグイン・テーマの削除（休眠中でも侵入経路になります）

費用感: ほぼ内製で対応可。ここを飛ばして更新に進むのは順番が逆です。

B案｜優先順にバージョンアップ（3〜6ヶ月）

10サイト×15〜20万 ＝ 150〜200万。金額として妥当な相場ではありますが、一度に飲む必要はありません。

  • 売上直結の順に分割（ギターの東大 → ドラム義塾 → 以降）。まず1サイトやって、崩れの程度と実工数を見てから残りを判断する
  • 技塾系サイトは共通テーマの流用のはず。1本目で直したパターンを横展開できるなら、2本目以降の単価は下がるはずです。ここは見積時に交渉材料になります
  • 順序に注意: PHPを先に上げるとWP側が動かなくなる可能性があります。原則は ステージング（複製）で検証 → WP更新 → PHP更新 → 本番反映。いきなり本番で上げない
  • ちなみに guitar-todai.net は WP 5.8.15 と PHP 8.1.34 の組み合わせで、これは本来推奨されない組み合わせです（動いてはいますが）

C案｜10サイト体制そのものを見直す（中期・①と接続）

10ドメイン分散は、更新コストも攻撃される面も10倍です。集約できれば運用は劇的に軽くなります。ただし各サイトが積んだSEO評価の移行リスクがあるため、今この場では決めないことを提案します。①の集客戦略（どこから問い合わせが来ているか）を見てから判断する論点です。具体的な進め方は次の「構成を変える3段」に整理しました。

「編集が重い」への対処（攻撃対策とは別枠）

原因はPHPだけではありません。無料でできる順・崩れリスクの低い順に並べると、実は更新を待たずに手が打てます。

  1. どこが重いのかの切り分け（今週・0円）
    管理画面全体か、特定の画面（投稿一覧・固定ページ編集）だけか、フロント表示も重いのか。ここで原因が3分の1に絞れます。
  2. データベースの掃除（0円・表示が崩れるリスクなし）
    投稿リビジョンの肥大、wp_options のautoload肥大、削除済みプラグインの残骸。管理画面の重さはこれで目に見えて改善するケースが多いです。バージョンに触らずに効きます。
  3. サーバーの世代とリソース競合
    xs022131.xsrv.jp は世代の古いサーバーです。エックスサーバーは新サーバーへの無料移行を提供していた実績があるので、対象かどうかの確認は価値があります（要確認）。10ドメイン同居の負荷もここに含まれます。
  4. PHP 8.3化
    ここは確実に効きますが、WP更新が先という順序は動かせません（WP 5.9はPHP 8.3では動きません）。つまり重さを根本から解こうとすると、結局B案に合流します。

費用ゼロで今日できる検証: guitar-todai.net だけ既にPHP 8.1で動いています。このサイトの管理画面と、7.4のサイト（例: adachionken.net）の管理画面で体感差があるかを触り比べていただけると、PHPを上げる効果が事前に読めます。差がはっきり出るなら更新の説得材料になり、差が出ないなら原因はDB側やプラグイン側なので、更新とは別に手を打つ話になります。

構成を変える3段（Cloudflare・静的化をどう入れるか）

長期的には、WordPressを10本抱えたまま守り続ける構成自体を変えたほうが、費用も安全性も速度も同時に良くなります。ただし運用するのは西さんなので、一度に全部は持てません。段を分けます。

1段目｜WPのまま、Cloudflareを手前に立てる（今月・低コスト） - DNSをCloudflareに向け、wp-login.php への国外アクセスとレート制限をカスタムルールで塞ぐ。フロントはキャッシュに乗せる - WordPressのバージョンに一切触らずに、攻撃を手前で止められて、表示速度も上がります - 注意: Cloudflare Proはドメイン単位課金で、10ドメインだと月200ドル規模。まずは無料枠＋カスタムルールで組むのが正解 - 効かない範囲: 管理画面の重さ（そこはDB掃除とPHP側の話）

2段目｜更新頻度の低いサイトを静的化して切り離す（3〜6ヶ月） - 日常更新がほぼないサイトを静的に落とせば、保守対象が10本→2〜3本に減ります。静的化したサイトは攻撃面がゼロになります - ここまで来ると、コードで直接管理する運用（Claude Code等）が現実的な選択肢になります - 前提: 各サイトの更新頻度と月間アクセスが分かれば、どれを切り離せるかは即決できます

3段目｜作り替え（来期・①とセット） - ①の集客戦略の結論（どのサイトから問い合わせが来ているか）を見てから投資判断

正直に申し添えると、2段目以降は当社が保守を持つ形にしないと運用が成立しません。アダチ音研様の費用の話と、当社の受注の話が混ざる提案になるので、そこは分けてお出しします。判断材料（更新頻度・アクセス数）だけ先にいただければ、混ぜずに整理できます。

エンジニアへ発注する場合の確認事項

インフィニックス社より安く請けられる、というのは合理的です（独自テーマは作った本人がいちばん速い）。ただし個人での受注になる分、やる前に決めておくことがあります。

  • 作業前の複製環境（ステージング）での検証は含まれるか
  • 表示崩れの修正は、どこまで対応範囲か（全ページか、主要ページのみか）
  • バックアップの取得と、失敗時の切り戻し責任
  • 作業後にどのバージョンまで上げるか、次回以降の更新は誰がやるのか
  • プラグインの定期更新（月次運用）を含めるか、別契約か
  • 作業内容の記録（何をどう直したか）の引き渡し

個人の方への発注が悪いという話ではなく、その方が対応できなくなった時にサイトが動かせなくなる状態を作らないための確認です。ここだけ押さえれば、コストメリットは素直に取れます。
