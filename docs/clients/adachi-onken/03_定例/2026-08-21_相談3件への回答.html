読み方

率は悪くありません。細いのは入口です。 39%・45%という通過率は、この種のテスト導線としては極端に悪い数字ではありません。仮に両方を1.5倍に改善しても、51名の入口のままでは筆記完了は9名→20名程度が上限です。目標人数から逆算して、バナーを見せる母数を何倍にするかを先に決めたほうが早いです。

そのために必要なのが「バナーの表示回数」です。押下51は分かっていますが、表示が500なのか5,000なのかで、直すべき場所（バナー自体か、その手前の集客か）が変わります。

  1. 筆記未完了11名へのリマインド（今週）。最も確実に数字が動きます。「あと◯問」「期限は◯日まで」を添える。

  3. フォーム送信 → 筆記の間をなくす。送信完了画面からそのまま筆記に入れる導線にする。メールを挟むほど落ちます。

③ WordPress のバージョンアップとセキュリティ

結論

「バージョンを上げれば安全になる」ではありません。 今回いちばんお伝えしたいのはここです。守り・更新・体制の3段に分けると、費用も判断もかなり軽くなります。

現状の危険度をどう見るか

いただいたバージョン一覧を見ると、10サイトすべてが 5.8系・5.9系です。数字だけ見ると「4世代前で放置」に見えますが、枝番に注目してください。5.8.15 / 5.9.16 という枝番は、そのブランチに出続けているセキュリティ修正が当たっている状態を示しています（WordPressは旧ブランチにも重要な修正を戻す運用）。つまりコア本体が穴だらけで放置、という状態とは少し違います。

危険度が高い順に並べ替えると、実際にはこうなります。

順位 リスク 現状 対処
1 ログインまわり（総当たり・使い回しパスワード・不要な管理者アカウント） 未確認 今週。費用ほぼゼロ
2 プラグイン・テーマの放置（独自テーマ10本＝作者しか直せない） 未確認 棚卸し後すぐ
3 PHP 7.4（2022年11月にサポート終了。言語側の修正がもう来ない） 6環境中5つが7.4系 更新とセット
4 バックアップと復旧手順 未確認 今週。ここが無いと何も試せない
5 コアのバージョン差 5.8/5.9系 計画的に

乗っ取り事例（wp2shell）をチェッカーで確認済みというのは良い初動です。ただしチェッカーは 特定の攻撃の痕跡を見るもので、「異常なし＝安全」ではありません。都度チェックではなく、仕組みで守る形に切り替えたいところです。

3つの方向性

A案｜守りを先に固める（今週〜2週間・低コスト）

崩れるリスクゼロで今すぐできることが、実はかなり残っています。

  • 管理画面へのアクセス制限（IP制限・国外アクセス遮断・ログイン試行回数制限）。エックスサーバーの標準機能で設定可能
  • 二要素認証の導入
  • 管理者アカウントの棚卸し（退任者・外注先のアカウントが残っていないか）
  • 自動バックアップの動作確認と、実際に戻せるかのテスト
  • 使っていないプラグイン・テーマの削除（休眠中でも侵入経路になります）

費用感: ほぼ内製で対応可。ここを飛ばして更新に進むのは順番が逆です。

B案｜優先順にバージョンアップ（3〜6ヶ月）

10サイト×15〜20万 ＝ 150〜200万。金額として妥当な相場ではありますが、一度に飲む必要はありません。

  • 売上直結の順に分割（ギターの東大 → ドラム義塾 → 以降）。まず1サイトやって、崩れの程度と実工数を見てから残りを判断する
  • 技塾系サイトは共通テーマの流用のはず。1本目で直したパターンを横展開できるなら、2本目以降の単価は下がるはずです。ここは見積時に交渉材料になります
  • 順序に注意: PHPを先に上げるとWP側が動かなくなる可能性があります。原則は ステージング（複製）で検証 → WP更新 → PHP更新 → 本番反映。いきなり本番で上げない
  • ちなみに guitar-todai.net は WP 5.8.15 と PHP 8.1.34 の組み合わせで、これは本来推奨されない組み合わせです（動いてはいますが）

C案｜10サイト体制そのものを見直す（中期・①と接続）

10ドメイン分散は、更新コストも攻撃される面も10倍です。集約できれば運用は劇的に軽くなります。ただし各サイトが積んだSEO評価の移行リスクがあるため、今この場では決めないことを提案します。①の集客戦略（どこから問い合わせが来ているか）を見てから判断する論点です。

「編集が重い」について

PHP 7.4 → 8.x は、管理画面の体感速度に効きます。ここは期待していただいて大丈夫です。ただし重さの原因はPHPだけとは限らず、プラグイン過多・投稿リビジョンの肥大・画像の未最適化・共有サーバーの負荷なども重なります。

費用ゼロで今日できる検証: guitar-todai.net だけ既にPHP 8.1で動いています。このサイトの管理画面と、7.4のサイト（例: adachionken.net）の管理画面で、体感差があるかを西さんに触り比べていただけると、PHPを上げる効果が事前に読めます。差がはっきり出るなら、更新の説得材料になります。

エンジニアへ発注する場合の確認事項

インフィニックス社より安く請けられる、というのは合理的です（独自テーマは作った本人がいちばん速い）。ただし個人での受注になる分、やる前に決めておくことがあります。

  • 作業前の複製環境（ステージング）での検証は含まれるか
  • 表示崩れの修正は、どこまで対応範囲か（全ページか、主要ページのみか）
  • バックアップの取得と、失敗時の切り戻し責任
  • 作業後にどのバージョンまで上げるか、次回以降の更新は誰がやるのか
  • プラグインの定期更新（月次運用）を含めるか、別契約か
  • 作業内容の記録（何をどう直したか）の引き渡し

個人の方への発注が悪いという話ではなく、その方が対応できなくなった時にサイトが動かせなくなる状態を作らないための確認です。ここだけ押さえれば、コストメリットは素直に取れます。
