## 技術スタック（判明分）

- フロント/アプリ: **Next.js 16.2.10 / React 19.2.4 / TypeScript / Tailwind 4**（実読で確定）。ORM は **Prisma 6.19.3**、認証は **next-auth v5(beta)** ＋ `AllowedUser`
- ホスティング: Vercel（社内ポータルと制作サイトが**別々のVercel構成・アカウントも別**）
- DB: Neon（PostgreSQL）
- 画像: **Cloudinary 無料プラン**（無料枠は月25クレジット≒25GB。2026-09-03「すぐ埋まるのでアウト」と確認）→ **Cloudflare R2 ＋ Cloudflare Images に移す方針**。制作原本(AI/PSD)のみ Google Drive
- 認証/ユーザーマスター: **Google Workspace のディレクトリを主体**にする方針（今月中に全ユーザー移行予定）

## 設計論点（詳細は議事録）

1. **店舗マスター連携**（最優先）— ポータル主体／組織図ツリーで承認フロー／確認者のデフォルト設定
2. **画像ストレージ移行** — Web表示は R2 ＋ Cloudflare Images、制作原本は Drive の店舗フォルダ。一覧はサムネ→クリックでDriveの原本を開く（※Driveから画像を直接表示するのは不可。`thumbnailLink` が数時間で失効・CORS制限・認証必須）
3. **スマホUI** — 依頼受付を最優先（現状「絶望的に見にくい」）。※全画面スマホファーストにはしない。制作チーム=PC・現場=スマホで画面ごとに最適化
4. **単価・在庫・請求** — 資材→発注→在庫の3段マスター、単価は改定日ベースで履歴保持。※在庫まで含めるとDB設計が重く長期化するのでスコープ判断が必要
5. **ナレッジ・アーカイブ** — 過去制作物のギャラリー化＋Notionビュー連携

## 決定事項（2026-09-03）

- **基盤は変えない**: Neon（DB）＋ Vercel（ホスティング）のまま
- **Cloudinary は廃止**（無料枠はすぐ埋まる／有料は実効 $0.415〜0.44/クレジット＝R2の28倍以上）
- **画像は用途で4層**: 構造化=Neon ／ Web表示する画像の実体=**Cloudflare R2** ／ 変換・配信=**Cloudflare Images（Transformations・月5,000変換まで無料）** ／ 制作原本=Google Drive
  - 要点は **R2をオリジンにして Images の変換だけ使う**（Imagesの保存料$5/10万枚・配信料$1/10万枚がかからない）
  - 線引きは **Web配信するものはR2、人が直接編集するものはDrive**
- **店舗マスタは案b**: 社内ポータルを正として日次バッチで一方通行同期（`Store.externalId` を追加）。※案a（直接接続/ビュー）は `Store.id` を7テーブルがFK参照しており不可
- **リアルタイムはDB移行不要**: ポーリング → Neon LISTEN/NOTIFY＋SSE → （必要なら）Supabase Broadcast／Presence（DB非依存）の順に段を上げる
- **追加費用は月1,000円未満の見込み**
