- **当面のゴール**: 制作システムは一旦1ヶ月程度で仕上げたい（2026-09-03 定例）
- **定例**: 毎週火曜15時。9/18(金)10:00＝全体結合、9/25(金)10:00＝制作サイト

## 技術スタック（判明分）

- フロント/アプリ: TypeScript（Next.js 系と推定 → 要確認）
- ホスティング: Vercel（社内ポータルと制作サイトが**別々のVercel構成・アカウントも別**）
- DB: Neon（PostgreSQL）
- 画像: **Cloudinary 無料プラン**（容量3TB・年間1TB弱増／添付10MB上限）→ **Google Drive へ移す方針**
- 認証/ユーザーマスター: **Google Workspace のディレクトリを主体**にする方針（今月中に全ユーザー移行予定）

## 設計論点（詳細は議事録）

1. **店舗マスター連携**（最優先）— ポータル主体／組織図ツリーで承認フロー／確認者のデフォルト設定
2. **画像ストレージ移行** — Drive の店舗フォルダ格納＋サムネイル表示→クリックでDriveを開く
3. **スマホUI** — 依頼受付をスマホファーストで最優先（現状「絶望的に見にくい」）
4. **単価・在庫・請求** — 資材→発注→在庫の3段マスター、単価は改定日ベースで履歴保持。※在庫まで含めるとDB設計が重く長期化するのでスコープ判断が必要
5. **ナレッジ・アーカイブ** — 過去制作物のギャラリー化＋Notionビュー連携

## 決定事項（2026-09-03）

- **基盤は変えない**: Neon（DB）＋ Vercel（ホスティング）のまま
- **画像は用途で3分割**: 構造化=Neon／配信サムネ=Cloudinary（無料枠）／制作原本・アーカイブ=Google Drive
- **店舗マスタは案b**: 社内ポータルを正として日次バッチで一方通行同期（`Store.externalId` を追加）
- **リアルタイムはDB移行不要**: ポーリング → Neon LISTEN/NOTIFY＋SSE → （必要なら）Supabase Broadcast の順に段を上げる
- **追加費用はほぼゼロ**
