# 店舗マスタDB（Neon）連携の整理 — 2026-09-03

社内ポータルで更新する店舗マスタDB（Neon）を、制作管理システムでも使えるようにするための現状整理とやることリスト。
出典: 2026-09-03 定例後に加藤（梨紗）さんが Claude と整理したもの。**9/18(金)10:00 定例のたたき台**として持ち込む。
議事録 → [2026-09-03 HASSIN様定例（初回）](../03_議事録/2026-09-03_HASSIN様定例（初回）.md)

## 現状

- 店舗マスタは**社内ポータル（店舗情報管理システム）側のNeon DBが正（マスタ）**という位置づけ
- 制作管理システム（梶原さん開発／Claude・Vercel・Neon）は**別Vercelプロジェクト・別アカウント**で動作。店舗データを独自に持っている可能性が高く、参照連携はされていない
- 権限: GitHub とポータル側DBは付与済み。**Neon招待は404で未解決**、**Vercel招待は阿部さん宛に送られており未着手**

## やること

| # | 項目 | 内容 |
|---|---|---|
| ① | 権限の解消 | Neon招待の再発行、Vercel招待先をバレンサー担当者へ再送 |
| ② | 連携方式の決定 | 下記3案から選ぶ。議事録の「マスターを1つに集約し両方に反映される形」というニュアンスからは **a か c が本命** |
| ③ | スキーマ設計 | 店舗ごとの組織図（承認フロー用ツリー）をマスタに保持。最終確認者／クリエイティブ確認者のデフォルト値＋店舗単位のプルダウン上書き |
| ④ | ユーザーマスタ連携 | Google Workspace ディレクトリを主体とする方針。今月中に全ユーザー移行完了予定のため、**設計確定後（9/18定例後）に着手**が現実的 |
| ⑤ | 次アクション | 9/18(金)10:00 の定例で「店舗マスター連携の設計」を最優先議題として詰める（合意済み） |

### ②連携方式の3案

| 案 | 方式 | 補足 |
|---|---|---|
| a | 制作サイトが社内ポータルのNeon DBへ**直接接続**（読み取り専用ロール／同一プロジェクト内のビュー経由） | 本命候補。実装が軽い |
| b | ポータルDBをSoT（単一の正）として **API/Webhookで制作サイト側に同期** | 疎結合だが同期の運用負荷が乗る |
| c | **単一Neonデータベースに統合**し、両アプリが同じ接続を使う | 本命候補。ただし2アプリの結合度が上がる |

> ⚠️ a/c を採る場合、**Vercelプロジェクトが別・アカウントが別**という現状が制約になる。①の権限解消が先。

## 案件依頼UIのレスポンシブ最適化

- 現状はPC前提の設計で、改良済みはダッシュボードのみ。**依頼受付は店舗側がスマホで見るメイン画面**なのに「スマホだと絶望的に見にくい」
- ⚠️ ただし**全画面をスマホファーストにはしない**。制作チームはPC・現場はスマホなので**画面ごとに主利用者を判定して最適化**する（→ [開発指示プロンプト](開発指示プロンプト.md)）

進め方:
1. 現行の依頼受付画面の項目棚卸し（担当者・工程・進捗%・印刷オプション＝トンボ付き/ラミネート等）
2. スマホ最適化で再設計 — 縦積みレイアウト、タップ領域の拡大、入力の多い箇所はウィザード（段階分割）形式を検討
3. 参考UIはホットペッパー／ぐるなび系の「フローティング条件バー」（画面下部固定のCTA/絞り込みバー）
4. 実装前に必ずHTMLモックアップを先出しし、文字・要素の重なりや挙動を確認してから本実装へ
