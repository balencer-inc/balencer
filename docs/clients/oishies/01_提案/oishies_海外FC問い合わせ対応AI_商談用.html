ナレッジ・メンテナンス・ループ ― 概念図

Google Drive上の既存マニュアルを正本候補とし、AIが「抜け・漏れ」を見つけ、現場と本部で継続的に改善する仕組み
既存のGoogle環境を活かす構成案
更新サイクル（6ステップ・循環）
Google Drive
唯一のナレッジ源
（移行・新規格納なし）
1
AIがDrive内マニュアルを精査し現状把握
2
抜け・漏れ・古い情報を自動検知しアラート
3
本部の定例MTGでバレンサー(AI)が概要を報告
4
バレンサー(AI)がマニュアル改訂の草案を作成
5
現場担当者をアサインしヒアリング・草案確認
6
ヒアリングを反映し磨いた上で本部承認→更新
技術構成の候補（レイヤー別）
1
ソース層Google Drive
既存のDocs / Sheets / PDFをそのまま参照。データ移行・再入力は行わない。
2
検索・索引層（RAG）NotebookLM Enterprise / Vertex AI Search
Drive内の変更を索引へ反映し、マニュアル更新がAIの回答にも反映される構成を検討。
3
ギャップ検知層Gemini / Claude API
「回答不能」「低確信度」の質問を自動フラグし、ログに記録。
4
集計・アラート層Apps Script + Cloud Scheduler
週次でギャップを自動集計し、定例ミーティング前にレポートを本部へ通知。
5
ドラフト生成層バレンサー(AI) = LLM
不足箇所の改訂案をGoogle Docs上に「ドラフト」として作成する想定。
6
ヒアリング・反映層既存チャット窓口 + Docs コメント
現場への確認方法と、回答をドラフトへ反映する流れを運用体制に合わせて設計。
ガバナンス：AIが正式マニュアルを無断で書き換えることはない。ドラフト作成と情報集約のみをAIが担い、正式反映は必ず本部承認を経て確定。Docsの変更履歴で誰がいつ何を直したか常に追跡可能。
