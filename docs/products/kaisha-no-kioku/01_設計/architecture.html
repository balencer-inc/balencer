バレンサーが既にやっていることを、繰り返し売れる形にするための構造図。下から上ではなく、資産・製造・工程・収益・複利の5層で読む。

LAYER 0

なぜ積むのか

前提。ここが揺れると全部が揺れる

コモディティ化したのは作る力であって、定着させる責任ではない

SUPPLY

供給は飽和した

制作の作業量・ツールの紹介・時間の切り売り。この3つだけが安くなった。AIで作業時間は30〜70%圧縮される。

守れない領域

DEMAND

需要は詰まったまま

日本企業のコア業務AI導入率1.9%（米6.1%）。生成AIパイロットの95%が測定可能な成果なし。断念は17%から42%へ。

詰まりの原因は組織

POSITION

立つ場所

作る力ではなく、会社の意思を構造化して、組織・ブランド・業務・AIに通しきる責任。ここに値札を付ける。

この構造の出発点

LAYER 1

何を持つか

資産。顧客の中に積み上がるもの

会社の記憶を8つのブロックで構造化して持つ

上段 A〜D ＝ 経営の層。会議に同席していないと書けないので、外注に落ちない核になる

A

会社の定義

何者か。何を大切にするか。どこへ行くか。

欠けると判断が揺れる

B

事業と商品

何を売るか。いくらか。何は売らないか。

欠けると安請け合いが止まらない

C

顧客

誰に届けるか。個別に誰で、何があったか。

欠けると担当交代で関係が消える

D

決め方

誰が何を決めるか。どの会議体で。何を基準に。

欠けると全部が社長決裁で詰まる

下段 E〜H ＝ 実装の層。A・Dが埋まらないままここだけ入れると、成果の出ないAI導入になる

E

業務の型

繰り返す仕事を、再現できる手順にしたもの。

欠けると属人化する

F

言葉とデザインの基準

対外に出るものの正誤判定基準。

欠けるとAIに書かせた瞬間に崩れる

G

記録の置き場ルール

どこに何を置くか。次に読む人とAIのために。

欠けると探す時間が最大コストになる

H

AIへの渡し方

人が読む形とAIが読む形を一致させる。

欠けると毎回ゼロから説明する

LAYER 2

誰がどう作るか

製造ライン。4領域が工程になる

既存の4領域が、そのままブロックの製造ラインになる

支援領域作るブロック作れる条件
組織開発・MVVA 会社の定義経営者と社員の対話。社員が自分の言葉で語れる状態まで
ブランド戦略・クリエイティブF 言葉とデザインの基準 ／ B の言語化会社の意味を、出るものの判定基準に落とす
デジタル・業務基盤E 業務の型 ／ G 置き場ルール現場の実務に入る。ヒトツがこの器に載る
AI実装H AIへの渡し方 ／ E の自動化現場で使われ、業務が実際に変わるところまで
経営伴走（CONSULT／PARTNER／EXECUTIVE）C 顧客 ／ D 決め方経営の会議に同席していること。資料として外から作れない

LAYER 3

どう納めるか

工程。90日で1周させる

90日で、記憶をv1にして1業務を動かし、手を離す

DAY 1—30

棚卸しと診断

記憶が今どこに散っているか。決め方の実態はどうか。A・B・C・Dの一次ドラフトを起こす。

出口 — 現在地の1枚と、触る1業務の決定

DAY 31—60

1業務のパイロット

最も回数の多い1業務をEとして書き出し、Hを最小実装して現場で動かす。

出口 — 現場が毎日使っている業務が1つ

DAY 61—90

定着と引き渡し

更新担当を決め、置き場ルールと更新手順を渡す。研修を1回。次の3業務の順番を決める。

出口 — 顧客が自分で更新できている状態

完了地点の定義 — バレンサーが抜けても回り、顧客が自分で記憶を更新できている状態。これを契約書に書く

LAYER 4

どう積むか

収益。新しい商品名は増やさない

入口を90日型に組み替え、成果物の名前を1つに束ねる

ENTRY

SPOT 経営整理

どのブロックが欠けているかを見る。30万円／回。

既存のまま

→

CORE

90日パッケージ

記憶v1を作り、1業務を動かし、引き渡す。固定価格＋25%バッファ。

新設。金額は未決

→

CONTINUE

CONSULT／PARTNER／EXECUTIVE

記憶を前提に相談し、施策を進め、決める側に入る。

既存のまま

BUILD

PROJECT 制作・開発・実装

記憶に沿って実物を作る。人月に寄せない。作業量ではなく、稼働し続ける状態への固定価格にする。

見積の型を改める

CONTAINER

ヒトツ（Notion業務基盤）

E・Gの器としてそのまま載る。既存商品の再定義で足りる。

新規開発は不要

課金の原則 — 時間ではなく成果パッケージの固定価格。AIで作業時間が縮むほど、人月換算は自社の減収に直結する

LAYER 5

どう強くなるか

複利。ここが回ると案件が資産になる

案件で得た型を共通側に還す。次は8割共通から組む

個別で作る

その会社にしかない中身（言葉・数字・決め方・業務）を作る。

2割

共通化できる型を抜く

工程・観点リスト・質問集・研修教材・引き渡し手順。

案件の最後に必ずやる

共通側に還す

スキルとテンプレに戻す。会話で終わらせずファイルにする。

評価指標はここ

次は8割共通から

ゼロから作らない。共通の骨格の上でだけ動く。

8割

測るのは納品量ではない。次の案件を共通側から何割で組めたかを記録する

GUARDRAIL

壊れ方

この4つで潰れる

先に壊れ方を決めておく

01

個別カスタマイズの泥沼

共通基盤がないまま毎回ゼロから作る。名前を変えただけの高稼働受託になる。

対策 — 8割共通の原則

02

燃え尽き

代表とディレクターへの一極集中。稼働の天井が売上の天井になる。

対策 — 3ヶ月区切りのポッド型

03

顧客の自走化失敗

抱え込んでブラックボックス化する。中小企業ほど耐性が低く、即解約になる。

対策 — 引き渡しを契約に書く

04

型が戻らない

発見が個人の頭とフォルダに残り、会社の資産が増えない。

対策 — 還元量で評価する
