# 充足度診断 — 質問集と採点表 v0.2

商品: 充足度診断 30万円／回・2週間（既存SPOT枠）
用途: 商談と初回訪問でそのまま使う。**この質問集と採点表が、共通側で唯一いま完成している資産**

> **Lv0〜3の定義は、この文書が正本。** 他の文書からは参照だけにする。

| 順 | やること | 誰が | 時間 |
|---|---|---|---|
| 1 | 事前アンケート（§2の24問）を渡す。**経営者1名＋社員2〜3名に別々に書いてもらう** | 顧客側 | 各30分 |
| 2 | 経営者インタビュー | 代表 | 120分 |
| 3 | 資料確認（会社案内・組織図・既存の手順書・共有ドライブの構成） | — | — |

## 2. 質問（8ブロック×3問）

聞き方の原則: 意見を聞かない。**事実と、直近に起きたことを聞く。**
アンケートは経営者と社員に同じ設問を配る。**答えのズレそのものが診断結果になる。**

### A｜会社の定義
1. この会社は何のためにあるのか、社員に説明するとしたら何と言いますか
2. 直近で判断に迷ったのはどの場面ですか。何を基準に決めましたか
3. 同じ質問を社員3人にしたら、同じ答えが返ってくると思いますか

### B｜事業と商品
1. いま一番利益が出ている仕事はどれですか。数字で分かりますか
2. 直近1年で断った仕事はありますか。何を基準に断りましたか
3. 値引きしてよいかどうかを、現場が自分で判断できますか

### C｜顧客
1. 主要な顧客との、これまでの経緯が書かれている場所はありますか
2. 担当者が急に辞めたら、その顧客の話を引き継げますか
3. 前回その顧客と何を話したかを、他の人が見られますか

### D｜決め方
1. 社長が決めていることのうち、本当は現場で決められるものはどれですか
2. 何を決める会議が、いつ開かれていますか
3. 決まったことは、どこに記録されていますか

### E｜業務の型
1. 社内で一番回数が多い仕事は何ですか
2. その仕事の手順は書かれていますか。最後に更新したのはいつですか
3. その仕事を、明日から別の人ができますか

### F｜言葉とデザインの基準
1. 会社案内・サイト・SNSで、言っていることは揃っていますか
2. 誰かが作った資料を、何を基準に良し悪し判断していますか
3. 外注先に渡している基準はありますか

### G｜記録の置き場ルール
1. 探しものに、1日どのくらい時間を使っていますか
2. 同じ資料が複数の場所にあることはありますか
3. 新しく入った人は、作った資料をどこに置きますか

### H｜AIへの渡し方
1. AIを使っている社員は何人いますか。何に使っていますか
2. AIに会社のことを説明する時、毎回ゼロから説明していますか
3. 導入したが定着しなかったツールはありますか。なぜ止まりましたか

## 3. 対象候補業務の測り方（診断の必須アウトプット）

**ここが90日に進むかどうかを決める。** 感覚ではなく数字で出す。

### 選ぶ基準

1. 回数が多く、複数人が日常的にやっている
2. 担当が固定されている（＝手順が取り出せる）
3. 失敗しても事業が止まらない

### 測る式

```
年間作業時間 ＝ 関わる人数 × 1人あたりの週の作業時間 × 50週
年間の人件費換算 ＝ 年間作業時間 × 3,000円／時（※顧客の実態に合わせて調整）
```

### 判定

| 年間作業時間 | 判定 |
|---|---|
| 1,000時間以上 | 90日パッケージの対象になる |
| 500〜1,000時間 | フェーズ1で止める。または対象業務を選び直す |
| 500時間未満 | **90日は勧めない。** 診断で終える |

**回収年数を必ず計算して見せる。2年で戻らないなら、その場で勧めない。**

## 4. 採点

| Lv | 状態 | 判定の目安 |
|---|---|---|
| 0 | ない | どこにも書かれていない |
| 1 | 個人の中 | 一人の頭の中にある。その人が抜けると消える |
| 2 | 書いてある | 文書はあるが、直近3ヶ月に更新されていない。または参照されていない |
| 3 | 使われている | 参照され、直近3ヶ月に更新されている |

### 採点のルール

1. **1ブロックにつき3問を採点し、一番低い問の値をそのブロックの値にする。** 迷ったら低いほうを付ける
2. **Lv2とLv3の分かれ目は「直近3ヶ月に更新されたか」の一点**で判定する
3. **経営者の回答と社員の回答が食い違うブロックは、社員側の値を採る。** 食い違いがあったこと自体を報告に書く（ここが一番効く指摘になる）
4. 診断時点の採点は**暫定**。フェーズ1の社員ヒアリングで確定する
5. **総合点を出さない。** 合計すると、どのブロックが空いているかという肝心の情報が消える

## 5. 返すもの（報告の1枚）

1. **8ブロックの暫定採点**（横棒。段階が読める形。レーダーチャートにしない）
2. **経営者と社員の回答が食い違ったブロック** — ここが一番の発見になる
3. **Lv0とLv1のブロック一覧** — 投資の候補
4. **対象候補業務3つと、それぞれの年間作業時間・人件費換算・回収年数**（§3）
5. **次の一手** — フェーズ1に進む／社内でやる／いま何もしない、の3択で示す

**やらないこと**: 総合スコアを出す。次の提案に繋げるための誘導を書く。**空いているブロックの提示は事実の報告であって、売り込みの導線ではない。**

## 6. よく出る形（仮説・実績n=0。1件ごとに書き換える）

現時点ではすべて仮説。**実測で埋まるまで、顧客にはこの表を見せない。**

| 採点の形 | 読み方 | 次の一手 |
|---|---|---|
| A=1、D=0、H=1 | 判断基準は社長の中にあり、決め方が定まっていない。AIは個人が勝手に使っている | 90日パッケージが最も当たる形 |
| A=2、F=2、E=0 | 理念とブランドは作ったが、現場の手順がない | Eを増やす提案 |
| E=2、G=1、H=0 | 手順はあるが散らばっていて、AIに渡せない | GとHに寄せた短縮版 |
| 全体が0〜1で、対象業務が年間500時間未満 | 口頭で回っている規模。仕組みを入れるには早い | **診断のみで終える。**採点の低さではなく、対象業務の量で判断する |

（最終行の判断根拠は採点ではなく§3の業務量。採点が低いことは、それ自体では受けない理由にならない。）
