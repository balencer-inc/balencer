## 0. この商品の位置づけ（先に決めておく）

- これは**会社の顔にしない**。バレンサーの定義は「経営と並走するブランディングカンパニー」のままで、この商品はその中の一本
- 主な対象は**既に伴走している顧客の深化**と、経営会議に入れる関係が作れる新規
- 90日ではF（言葉とデザインの基準）を直接は触らないが、**A（会社の定義）の言語化はFの上流**にあたる。判断基準を言葉にする仕事は、対外表現の基準の土台になる。ここが繋がっていることを、社内でも商談でも外さない

## 1. 最初に決めること — 全部を一度に売らない

A〜Hを1本で全部やると、45人日を大きく超えて価格が跳ね、対象企業の決裁が下りない帯に出る。かといって8つをバラバラのメニューにすると、今と同じ（案件ごとに形が違う）に戻る。

**採る構造。**

> **最小の1周を90日で回し、残りは継続契約の中で埋める。**
> **90日は45日で一度切り、そこで止められるようにする。**

45日で切る理由は2つ。①顧客が148万円から入れて、価値を見てから残りを決められる ②同席が取れない・現場が動かないといった前提崩れを、実装に入る前に検出できる。

## 2. ブロックごとのサービス定義

終わりの判定基準がないブロックは売れない（終われないから）。判定は**人に聞けば分かる形**で書く。

### A｜会社の定義
- **渡すもの**: 経営者の判断基準を言葉にしたもの（何を大切にし、迷った時に何で決めるか）
- **作り方**: 経営者インタビュー2回 → 社員ヒアリング3名 → 言語化 → 経営者と突き合わせ
- **所要**: 全社浸透まで1〜3ヶ月。**90日では経営者の判断基準の言語化まで**（社内呼称: A簡易。対外では「経営者の判断基準の言語化」と書き下す）
- **終わりの判定**: 社員3人に別々に聞いて、同じ意味のことが返ってくる
- **単独販売**: 可（MVV策定として実績あり）

### B｜事業と商品
- **渡すもの**: 何を売るか・いくらか・何は売らないか・誰が担うか
- **作り方**: 既存の見積と請求と実績から実態を洗う → 経営者と突き合わせる → やらないことを決める
- **所要**: 2〜4週間
- **終わりの判定**: 現場が値引きの可否を自分で判断できる
- **単独販売**: 不可（Aがないと判断の基準が作れない）

### C｜顧客
- **渡すもの**: 顧客名簿と、関係の履歴が1箇所にある状態
- **作り方**: 台帳・メール・個人の記憶を集約 → 更新の担当と頻度を決める
- **所要**: 2〜4週間＋定着
- **終わりの判定**: 担当が変わっても、前任と同じ話ができる
- **単独販売**: 可。ただし単体だとCRM導入（顧客管理システムの導入）と区別が付かず値段を比較される

### D｜決め方
- **渡すもの**: 誰が何を決めるか／どの会議体で／何を基準に／何はやらないか
- **作り方**: **経営会議に同席して実態を観察** → 決裁の詰まりを特定 → 権限の線を引き直す → 経営者の合意
- **所要**: 2〜3ヶ月。**90日では詰まりの特定と、権限移譲を1件実行するところまで**
- **終わりの判定**: 社長決裁だったものが1つ以上、現場決裁に移っている
- **単独販売**: 不可（同席が前提）

### E｜業務の型
- **渡すもの**: 対象業務の手順書と、例外の扱い
- **作り方**: 現場に張り付いて観察 → 手順化 → 現場に直させる
- **所要**: 1業務あたり3〜4週間
- **終わりの判定**: その業務を知らない人が、手順だけで7割できる
- **単独販売**: 可（業務改善として）

### F｜言葉とデザインの基準
- **渡すもの**: 使う言葉／使わない言葉／見た目の基準／出す前の判定手順
- **作り方**: 既存の対外物を棚卸し → ブレを特定 → 基準化 → チェックの仕組みを渡す
- **所要**: 3〜6週間
- **終わりの判定**: 別の人が作ったものを、基準だけで合否判定できる
- **単独販売**: 可（ブランドガイドラインとして実績あり）
- **90日では触らない**。ただしAの言語化がここの土台になるので、次の提案として最も自然に繋がる

### G｜記録の置き場ルール
- **渡すもの**: どこに何を置くか・命名・権限・捨て方
- **作り方**: 散らばりを可視化 → 置き場を決める → 移す → ルールを渡す
- **所要**: 3〜6週間。**90日では対象業務まわりだけ**（社内呼称: G最小）
- **終わりの判定**: 新しい資料が、言わなくても正しい場所に置かれる
- **単独販売**: 可

### H｜AIへの渡し方
- **渡すもの**: A〜Gの内容をAIが読める形にしたものと、**対象業務で稼働するAIの試作**
- **作り方**: A〜Gから構造化 → AIに読ませる → 対象業務で試験運用 → 現場で調整
- **所要**: 3〜4週間（A・D・Eが埋まっていて、かつ顧客環境へのアクセスが取れていれば）
- **終わりの判定（90日時点）**: **現場の担当者が、指示なしで週3回以上使っている**
- **日常への完全な定着は90日の外**。継続契約で見る。ここを90日の必達にすると、必ず期限に間に合わない
- **単独販売**: 不可

## 3. 単独で売れるもの・売れないもの

| | ブロック | 理由 |
|---|---|---|
| 単独で売れる | A・C・E・F・G | 単品での受注実績がある（C・Gの単独実績は要確認 → §9） |
| 単独で売れない | **B・D・H** | Bは基準（A）が要る。Dは同席が要る。HはA・D・Eが要る |

**単独で売れないB・D・Hのうち、H（AI）が一番求められる。** ここが商談の勝負どころになる。

## 4. 断り文句への返し

商談で必ず出る4つ。返しを型にしておく。

| 言われること | 返し |
|---|---|
| **AIだけ入れてほしい** | AIを載せること自体は3〜4週間でできます。ただし今の状態で載せると、動かない側に入る確率が高い。先に決め方と、対象業務の手順を見せてください。そこが埋まっていれば、AIは最後の1ヶ月で載ります |
| **高い** | 対象業務の年間作業時間を人件費に換算して、何年で戻るかを一緒に見ます。**2年で戻らないなら、この商品はお勧めしません。**（診断で必ず計算する。届かない会社には売らない） |
| **社内でもできそう** | できます。実際、A・E・Gは社内でやり切った会社もあります。ただし**決め方（D）だけは社内では動きにくい**。社長の決裁を減らす話を、社員から言い出すのは難しいからです。そこだけ外から入る、という使い方でも構いません |
| **補助金は使えないのか** | 現行の規定では、このままでは通らない可能性が高いです。役務が主体の構成は対象外になりやすく、時間単価の上限もあります。使うなら製品部分を別に立てる必要があるので、それは別の設計として考えます |

**高い、への返しが一番重要。** 回収年数が2年を超える会社には売らないと決めておけば、値段の議論が数字の議論になる。

## 5. 商品の組み方（3段＋フェーズ分割）

| 段 | 商品 | 期間 | 中身 |
|---|---|---|---|
| 入口 | 充足度診断（既存SPOT枠） | 2週間 | 8ブロックの暫定採点と、対象候補業務3つの年間工数の算定 |
| 本命・前半 | **フェーズ1｜現在地と決め方** | Day 1〜45 | A（判断基準の言語化）＋D（詰まりの特定と権限移譲1件）＋対象業務の確定 |
| 本命・後半 | **フェーズ2｜型化と実装** | Day 46〜90 | E1本＋H（試作稼働）＋G最小＋研修＋引き渡し |
| 継続 | CONSULT／PARTNER／EXECUTIVE | 6ヶ月〜 | 残りのブロックを埋める |

**フェーズ1で終わってよい。** これを商談でこちらから先に言う。前提が崩れている会社を無理に後半へ進めない。

**90日で触らないもの**: B・C・F と、Aの全社浸透、Eの2本目以降。範囲を広げないことが、このパッケージの品質そのものになる。

## 6. 前提が崩れた時の扱い（撤退線）

現場で必ず起きることに、先に線を引いておく。

| 起きること | 扱い |
|---|---|
| 経営会議に同席させてもらえない | **フェーズ1のみで終える。** フェーズ2に進まない。Dが作れない状態で実装だけ進めない |
| 同席が2回に満たない | Dは詰まりの特定までとし、権限移譲の実行は継続契約へ送る。**フェーズ1の金額を調整する**（§pricing） |
| Day30を過ぎて対象業務が確定しない | フェーズ2の開始を後ろ倒しにする。無償で吸収しない |
| Day75時点でAIが現場で使われていない | Hは**手順書とAIへの指示文一式の引き渡し**に切り替えて完了とする。無償延長しない |
| 更新担当者が抜けた | 正副2名を最初から指定してもらう。1名指定は単一障害点 |
| 顧客が資料を出さない | Day15時点で出ていないものは、対象範囲から外して記録に残す |

## 7. なぜこの順番なのか

- **A・Dを先にやる**: 決め方が決まっていない会社に道具だけ入れると、承認が通らず現場で止まる
- **Eを1本に絞る**: 求められているのは大戦略ではなく、週単位で体験できる改善。まず小さく動くものを1つ
- **Hを最後にする**: A・D・Eが揃っていればAIは3〜4週間で載る。逆にここから始めると、載せる先がない
- **B・C・F・Gを後に回す**: 90日の範囲を超えるうえ、A・Dが埋まってからのほうが速く正確に作れる

**外部データの扱い**: OECD（2025-12、中小企業対象）では日本企業のコア業務でのAI導入率が1.9%、MIT NANDA（2025、大企業のパイロット対象）では95%が測定可能な成果に至っていない。**調査対象が違うので、日本の中小企業にそのまま当てはめない。** 順番の話とこれらの数字は「同じ方向を指している」までで止める。因果として断定しない。

## 8. 8割共通・2割個別（このサービスの資産）

現時点で**実在するのは診断の質問集と採点表だけ**。残りはこれから作る。作った順に印を更新する。

| 共通（毎回そのまま使う）＝ 8割 | 状態 | 個別（その会社にしかない）＝ 2割 |
|---|---|---|
| 充足度診断の質問集と採点表 | **あり** | 採点の結果 |
| ブロックごとの終わりの判定基準 | **あり** | 判定に使う具体 |
| 90日の工程と各期の出口 | **あり** | 対象業務の選定 |
| 断り文句への返し | **あり** | — |
| 撤退線と事故対応 | **あり** | — |
| 会議同席時の観察の観点（Dの作り方） | 未 | 決裁の詰まりが誰か |
| 業務観察から手順化までのフォーマット（Eの作り方） | 未 | 業務固有の例外 |
| AIへの読ませ方の型（Hの作り方） | 未 | 読ませる中身 |
| 研修カリキュラムと教材 | 未 | — |
| 引き渡し手順と更新ルールの雛形 | 未 | — |

**未が5つある間は、代表以外がこの商品を回せない。** 1件目を回しながら5つを作る。それが1件目の本当の目的になる。
